# WEOS Terms

This glossary scopes terms instead of forcing one definition where repository
sources conflict. Runtime enum values are not canonical concepts unless the
artifact, record type and authority boundary are also identified.

| Term                         | Canonical definition if available                                                      | Runtime usage                                                                                                                    | Conflicting uses                                                                        | Not equivalent to                             | Evidence                                                                         | Unresolved ambiguity                                                      |
| ---------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `artifact`                   | Governed content or operational object under WEOS                                      | Cases, revisions, registry entries, education, graph candidates, evidence and reasoning paths                                    | Sometimes row, JSON component or generated content                                      | Route, role, command                          | `WEOS-IMP-003`; `docs/weos/capability-map/WEOS-CAPABILITY-MAP.md`                | Exact boundary differs by artifact family                                 |
| `identity`                   | Stable way to refer to an artifact across changes                                      | Registry IDs, case IDs, revision IDs and ordered clue JSON                                                                       | Ordered JSON may be mistaken for stable identity                                        | Revision, status                              | `WEOS-OD-001`; `WEOS-OD-007`                                                     | Stable clue identity remains open                                         |
| `APPROVED`                   | A governed decision on an exact artifact/revision in `WEOS-IMP-003`                    | `CaseEditorialStatus.APPROVED`; `DiagnosisEducationStatus.APPROVED`; graph candidate `APPROVED`; teaching rule string `APPROVED` | Sometimes status projection, sometimes decision result, sometimes pre-publication state | `PUBLISHED`, `ACTIVE`, `READY_TO_PUBLISH`     | `schema.prisma`; `WEOS-IMP-004-legacy-status-crosswalk.md`                       | Which runtime approvals have canonical decision records                   |
| `ACTIVE`                     | Standing for active artifacts or operational visibility depending artifact             | `DiagnosisRegistryStatus.ACTIVE`; `DiagnosisGraphFactStatus.ACTIVE`; teaching/evidence relationship active                       | Can mean dictionary-visible, fact usable, teaching relationship usable, or rule active  | `APPROVED`, `PUBLISHED`                       | `schema.prisma`; lifecycle docs                                                  | Whether every active transition requires same authority                   |
| `READY_TO_PUBLISH`           | Readiness, not publication                                                             | `CaseEditorialStatus.READY_TO_PUBLISH` after `markReadyToPublish`                                                                | Legacy/current status may be mistaken for publication authorization                     | `PUBLISHED`, publication decision             | `case-review.service.ts`; `WEOS-IMP-004`                                         | Whether readiness decision is persisted canonically                       |
| `PUBLISHED`                  | Publication standing must target exact published version                               | `CaseEditorialStatus.PUBLISHED`; `DiagnosisEducationStatus.PUBLISHED`; `DailyCase` exposes published cases                       | Case/education status and daily schedule can be conflated                               | Approval, schedule, release, learner exposure | `schema.prisma`; `WEOS-IMP-002`; `WEOS-IMP-005`                                  | Published artifact version/history model open                             |
| `REVIEW_REQUIRED`            | Phase/doc disposition or validation/trust state needing review                         | Phase 2 docs disposition; AI/reasoning statuses                                                                                  | Document review and content review share phrase                                         | `NEEDS_REVIEW`, rejection, failure            | `WEOS-IMP-005`; `schema.prisma`                                                  | Whether doc status and runtime status vocabularies should remain distinct |
| `NEEDS_REVIEW`               | Artifact lifecycle state requiring review                                              | Education status, candidate status, runtime string statuses                                                                      | Similar to `REVIEW_REQUIRED` but not identical                                          | `REVIEW_REQUIRED`, `NEEDS_EDIT`               | `schema.prisma`; `WEOS-IMP-004`                                                  | Controlled vocabulary for string fields                                   |
| `lifecycle`                  | Governed sequence of artifact states and transitions                                   | Runtime status fields and canonical transition metadata                                                                          | Can be reduced to mutable status fields                                                 | Permission, readiness, publication            | `WEOS-IMP-002`; `docs/weos/capability-map/RUNTIME-ACTION-CROSSWALK.md`           | Which lifecycle transitions need governance records                       |
| `readiness`                  | Evaluation of prerequisites, not lifecycle itself                                      | Diagnosis lifecycle readiness, publication readiness, reasoning readiness score                                                  | May be shown as status in dashboards                                                    | Approval, active, published                   | `diagnosis-registry-lifecycle-policy.service.ts`; capability map                 | Which readiness checks must persist records                               |
| `operational permission`     | Governed permission to use an artifact operationally                                   | `DiagnosisRegistry.isPlayable`; `DiagnosisRegistry.isGeneratable`                                                                | Can be conflated with active or published                                               | Dictionary-visible, published, approved       | `docs/weos/capability-map/DATABASE-MODEL-MAP.md`; `WEOS-OD-012`                  | Expiry/review metadata open                                               |
| `validation result`          | Output of a validation run                                                             | `ReasoningDraftValidationRun`                                                                                                    | May be mistaken for approval                                                            | Governance decision, publication authority    | `docs/weos/capability-map/DATABASE-MODEL-MAP.md`; reasoning validation service   | Whether validation rows are append-only and how standing is computed      |
| `validation standing`        | Current trust/freshness of prior validation                                            | Reasoning validation freshness not fully implemented                                                                             | Prior run may be read as still valid                                                    | Approval, lifecycle status                    | `WEOS-OD-009`; `docs/weos/gaps/IMPLEMENTATION-GAPS.md`                           | Persisted versus computed staleness                                       |
| `assessment`                 | Structured evaluation artifact                                                         | Assessment tables are not fully modeled in the current interpretation layer                                                      | Review or validation may be treated as assessment                                       | Governance decision, validation run           | `WEOS-OD-010`                                                                    | Assessment family modeling remains open                                   |
| `review`                     | Human or editorial evaluation workflow                                                 | `CaseReview`, education review, graph candidate review                                                                           | Review row may be treated as governance envelope                                        | Publication authorization, generic decision   | `docs/weos/capability-map/DATABASE-MODEL-MAP.md`; permission map                 | Which reviews require separate canonical decisions                        |
| `decision`                   | Governed outcome by an authorized actor                                                | Review decisions, candidate decisions, status writes                                                                             | Mutable fields may be mistaken for decisions                                            | State projection, service log                 | `WEOS-IMP-003`; `docs/weos/gaps/IMPLEMENTATION-GAPS.md`                          | Generic versus typed envelope                                             |
| `approval`                   | Positive governed decision on a target artifact/revision                               | Case, education, graph and clue approval-like statuses                                                                           | May be coupled to publication or promotion                                              | Publication authorization, promotion          | `docs/weos/capability-map/RUNTIME-ACTION-CROSSWALK.md`; glossary                 | Which approvals have canonical records                                    |
| `publication authorization`  | Authority to publish a specific artifact version                                       | Case readiness and education publish paths                                                                                       | Often coupled to approval/status                                                        | Readiness, schedule, exposure                 | `WEOS-OD-008`; `WEOS-OD-011`; `WEOS-OD-014`                                      | Exact decision and actor model open                                       |
| `published artifact version` | The exact content version released or exposed                                          | Not first-class for cases; education revision targeting is coupled to review                                                     | Current row status may be treated as exact version                                      | Schedule, release, approval                   | `docs/weos/capability-map/DATABASE-MODEL-MAP.md`; implementation gaps            | Published-version target remains open                                     |
| `schedule`                   | Planned date/track/slot for exposure                                                   | `DailyCase`                                                                                                                      | May be treated as publication authority                                                 | Publication decision, release                 | `DailyCasesService`; database map                                                | Generic schedule model remains open                                       |
| `release`                    | Operational act of making a version available                                          | Daily gameplay exposure and education publication status                                                                         | Can be conflated with schedule or approval                                              | Publication authorization, readiness          | `WEOS-IMP-002`; implementation gaps                                              | Release/exposure boundary remains open                                    |
| `learner exposure`           | Learner-facing availability of an artifact                                             | Daily cases and playable registry state                                                                                          | Can be conflated with publication status                                                | Publication authorization, schedule           | `DailyCase`; `DiagnosisRegistry.isPlayable`                                      | Withdrawal and exact exposure history remain open                         |
| `withdrawal`                 | Governed ending of publication or exposure                                             | No first-class withdrawal model identified                                                                                       | May be inferred from status changes                                                     | Deletion, deactivation                        | `WEOS-OD-014`                                                                    | Exposure-ending command model open                                        |
| `archive`                    | Move an artifact out of active use while preserving history                            | Education archive action, graph fact archive-like statuses                                                                       | May be conflated with deprecation or deletion                                           | Withdrawal, deletion                          | `docs/weos/capability-map/RUNTIME-ACTION-CROSSWALK.md`                           | Artifact-specific semantics differ                                        |
| `supersession`               | Explicit replacement of one authoritative artifact/source by another                   | Document and draft states may imply but not prove it                                                                             | Newer file may be treated as superseding older file                                     | Review, generation, modification date         | `docs/weos/authority/STATUS-AND-PRECEDENCE.md`; `WEOS-OD-021`                    | Protected-field change authority open                                     |
| `deprecation`                | Marking an artifact as no longer preferred/active without deletion                     | Registry and graph statuses                                                                                                      | May be treated as hidden or removed                                                     | Deletion, archive                             | `WEOS-OD-013`; `WEOS-OD-015`                                                     | Replacement/searchability policy open                                     |
| `apply`                      | Controlled application of accepted candidate, not approval                             | Clue draft apply mutates case and creates `CaseRevision`                                                                         | May be read as approval or publication by humans                                        | Publish, approve, accept                      | `diagnosis-editorial-workspace.service.ts`; `WEOS-IMP-003`                       | Generic controlled application record absent                              |
| `controlled application`     | Governed operation that applies an accepted candidate to runtime state                 | Clue draft application updates case state/revisions                                                                              | May be collapsed into acceptance                                                        | Approval, publication                         | Runtime-action crosswalk; implementation gaps                                    | Generic controlled-application record and authority open                  |
| `publish`                    | Publication/release/exposure are separate canonical concepts                           | Case daily publishing, education publish status, ready-to-publish                                                                | Often mixed with schedule/release/readiness                                             | Approve, ready, schedule, expose              | `daily-cases.service.ts`; `diagnosis-education.service.ts`; `WEOS-IMP-002`       | Generic publication history/version model open                            |
| `candidate`                  | Proposed artifact pending review                                                       | Registry candidate, graph candidate, teaching rule candidate                                                                     | Candidate may later create fact/registry/rule but is not itself final                   | Fact, active registry, approved record        | `schema.prisma`; graph/registry services                                         | Promotion and approval boundaries                                         |
| `fact`                       | Promoted graph knowledge artifact                                                      | `DiagnosisGraphFact` active/archived                                                                                             | Fact can be created during candidate approval                                           | Candidate, evidence node                      | `schema.prisma`; `diagnosis-graph-candidates.service.ts`                         | Whether fact creation needs separate authority                            |
| `standing`                   | Current lifecycle/visibility/permission state of existing artifact                     | Encoded in status booleans and canonical metadata `changesStandingOfArtifactTypes`                                               | Often implemented as mutable fields                                                     | Created record, immutable decision            | `canonical-actions.ts`; `WEOS-IMP-003`                                           | Which standing changes need audit records                                 |
| `governance record`          | Record of why, authority, rationale, effect                                            | `CaseReview` and audit rows exist; `CaseEditorialDecision` is `UNAVAILABLE_IN_BRANCH`; many domains lack a generic envelope      | Sometimes service logs or row fields stand in                                           | Audit event alone, status field alone         | `docs/weos/capability-map/DATABASE-MODEL-MAP.md`; `WEOS-IMP-005`                 | Generic vs typed record design                                            |
| `editorial decision`         | Governed outcome under authority                                                       | Review decisions and canonical `EDITORIAL_DECISION`; `CaseEditorialDecision` is `UNAVAILABLE_IN_BRANCH`                          | Runtime `ReviewDecision` and status transitions are not always separate records         | Review workflow, assessment, validation       | `docs/weos/capability-map/DATABASE-MODEL-MAP.md`; `WEOS-IMP-003`                 | Cross-artifact decision envelope                                          |
| `audit event`                | Event that something happened                                                          | Service logs and audit-oriented rows exist; `CaseReviewEvent` is `UNAVAILABLE_IN_BRANCH`                                         | Logs may be confused with persisted audit records                                       | Governance record, editorial decision         | `docs/weos/capability-map/DATABASE-MODEL-MAP.md`; services                       | Which logs are sufficient, if any                                         |
| `revision`                   | Versioned content snapshot                                                             | `CaseRevision`, `DiagnosisEducationRevision`; version fields on other models                                                     | Some artifacts have versions without revision tables                                    | Current mutable row, approval                 | `schema.prisma`; `WEOS-IMP-005`                                                  | Teaching/reasoning revision models open                                   |
| `compatibility projection`   | Mutable compatibility/current state derived from or standing in for canonical concepts | `Case.editorialStatus`, `approvedAt`, `DiagnosisRegistry` flags                                                                  | Projections may be mistaken for canonical records                                       | Governance record, immutable history          | `WEOS-IMP-001`; `WEOS-IMP-004`; `docs/weos/capability-map/DATABASE-MODEL-MAP.md` | Synchronization strategy open                                             |
| `runtime role`               | Application role used by guards/helpers                                                | `user`, `editor`, `senior_editor`, `admin`                                                                                       | May be treated as institutional authority                                               | Canonical authority, technical actor          | `docs/weos/capability-map/PERMISSION-MAP.md`; `auth/roles.ts`                    | Role-to-authority assignment unregistered                                 |
| `canonical authority`        | WEOS authority to make a governed decision                                             | Not proven by route access                                                                                                       | Senior/admin route access may be overread                                               | Runtime role, route permission                | `docs/weos/capability-map/PERMISSION-MAP.md`; open decisions                     | Authority assignment policy open                                          |
| `state gate`                 | Runtime precondition based on artifact state                                           | Status checks before service mutation                                                                                            | May be treated as permission                                                            | Route permission, canonical authority         | `docs/weos/capability-map/PERMISSION-MAP.md`; runtime-action crosswalk           | Gate consistency differs by path                                          |
| `route permission`           | Runtime access check at controller/guard level                                         | `@EditorialAccess`, `@SeniorEditorialAccess`, `AdminGuard`                                                                       | May be generalized beyond exact method                                                  | Service-level authority, canonical authority  | `docs/weos/capability-map/PERMISSION-MAP.md`                                     | Service-level actor authority mostly absent                               |
| `technical actor`            | System, script or service identity performing operations                               | Seeds, backfills, generation scripts and services                                                                                | May be confused with human authority                                                    | Institutional authority, runtime role         | Test-command map; open decisions                                                 | Backfill and emergency authority policies open                            |
| `institutional authority`    | Human or organizational authorization outside runtime roles                            | Not encoded by current role helpers                                                                                              | May be inferred from `senior_editor` or `admin`                                         | Canonical authority, route permission         | `docs/weos/capability-map/PERMISSION-MAP.md`; implementation gaps                | Assignment policy unregistered                                            |
| `material change`            | Change significant enough to require invalidation/review                               | Distributed invalidation reasons and draft workflows                                                                             | May be conflated with approval                                                          | Validation result, publication                | `WEOS-OD-017`                                                                    | Storage location remains open                                             |
| `expected version`           | Command input declaring the version the actor intends to mutate                        | Not generally present in governed mutation commands                                                                              | Unique revision number may be mistaken for it                                           | Uniqueness constraint, transaction            | Database map; implementation gaps                                                | Generic command contract open                                             |
| `stale validation`           | Validation whose standing changed after dependent material changes                     | Reasoning validation staleness is unresolved                                                                                     | Prior validation may be treated as current approval                                     | Failed validation, approval                   | `WEOS-OD-009`; implementation gaps                                               | Persisted/computed standing policy open                                   |
| `branch-missing evidence`    | Worktree/local/planned item absent from committed `HEAD`                               | `FILE_NOT_IN_BRANCH`, `UNAVAILABLE_IN_BRANCH`, `WORKTREE_ONLY`, `PLANNED` classifications                                        | Local files may be mistaken for committed capability                                    | Active implementation                         | Capability map; database map; gap register                                       | Must be revalidated after commit/branch changes                           |
| `playable`                   | Operational permission for diagnosis/case eligibility                                  | `DiagnosisRegistry.isPlayable`; case eligibility policy                                                                          | Can be conflated with active or published                                               | Dictionary-visible, generatable, approved     | `schema.prisma`; `diagnosis-registry-lifecycle-policy.service.ts`                | Expiry/review metadata open                                               |
| `dictionary-visible`         | Runtime visibility in diagnosis dictionary/search                                      | `DiagnosisRegistry.status ACTIVE`, `active`, `isPlayable` in lifecycle telemetry                                                 | May be conflated with active registry alone                                             | Playable, generatable, published              | `diagnosis-registry-lifecycle-policy.service.ts`                                 | Exact canonical artifact boundary                                         |
