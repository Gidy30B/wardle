# WEOS Test and Command Map

This map is a durable test and verification contract for agents working on the
WEOS capability-map and runtime implementation. It records command availability,
execution boundaries, write risks and proof limits. It does not claim that a
configured command passes unless an execution record is explicitly present.

## Verification Metadata

- Last verified commit: `c482df9889f8b342abac1db7537a6072cbc9605f`
- Last verified date: `2026-07-27`
- Verified branch: `weos/phase-2-review`
- Runtime/configuration evidence: committed `HEAD`
- Local uncommitted runtime, dashboard, test and configuration files: excluded
  from command availability claims
- Execution policy: a configured command is not treated as passing unless
  execution is recorded
- Verification commit availability: confirmed in the local repository; remote
  availability not independently verified

## Interpretation Warning

A command existing in repository configuration does not prove that it passes.

A passing test proves only the behavior directly exercised by that command and
its selected test files. It does not establish complete route coverage,
production behavior, database safety, canonical authority, formal document
approval or end-to-end correctness unless the command explicitly tests those
properties.

## Status Model

Configuration status values:

- `CONFIGURED`: the exact command is present in committed package configuration
  or can be constructed from committed executable files.
- `FILE_NOT_IN_BRANCH`: a required command source, test file or configuration
  file is absent from committed `HEAD`.
- `COMMAND_NOT_FOUND`: the documented script name is not present in committed
  package configuration.
- `CONFIGURATION_UNKNOWN`: repository evidence is insufficient.

Execution status values:

- `PASSED`
- `FAILED`
- `NOT_EXECUTED`
- `SKIPPED`
- `BLOCKED_BY_ENVIRONMENT`
- `EXECUTION_UNKNOWN`

## Command Safety Summary

### Read-Only or No Expected Source Writes

Focused Jest tests, configured dashboard Node tests, Prettier checks, Git diff
checks, staged scope checks, path checks and file inventory have no expected
source writes. Caches, traces, test results, logs or package-manager metadata may
still be written depending on local tooling and environment.

### Worktree-Mutating

`npm run weos:docs:generate`, `npm run weos:docs:check`, backend `npm run lint`
and any Prettier `--write` command can modify tracked source or generated
documents. Treat them as worktree-mutating unless a narrower dry-run/check
command is sufficient.

### Build/Cache Generating

Backend build, dashboard build, coverage, Playwright and Jest commands may write
build output, coverage, caches, traces or test artifacts. These writes are not
the same as source changes, but they can affect the local workspace.

### External-State Dependent or Potentially Mutating

Browser QA requires live services and seeded data. E2E tests must be inspected
for database effects before execution. Seeds, backfills, imports, migrations and
generation scripts may modify a database; such commands are not safe to infer
from test naming alone and are not part of this documentation verification task.

## Agent Command-Selection Rule

Before running a command, an agent must determine:

1. Whether the exact command is configured in committed `HEAD`.
2. Whether required files exist in committed `HEAD`.
3. Required environment variables, services, browsers and data.
4. Whether the command writes source files.
5. Whether it writes build artifacts, caches, traces or coverage.
6. Whether it may modify a database, queue or remote system.
7. What behavior the command directly proves.
8. What behavior remains outside its coverage.
9. Whether prior staged or unstaged work must be protected.
10. Whether a narrower command can answer the verification question safely.
